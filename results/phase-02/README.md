# Phase 2 raw evidence

Everything here was produced by the AI implementation assistant in an ephemeral Linux x86_64 cloud
container (4 vCPUs, Intel Xeon @ 2.10 GHz, shared host), **not** on the owner's machine and not in
GitHub Actions. Nothing has been independently reproduced. The container had no git repository, so
`git_commit` reads "not a git repository": the code is the owner's `d65152f` plus the uncommitted
Phase 2 changes. Re-running the scripts overwrites these files.

- `gcc/`, `clang/`: `scripts/verify-presets.sh <compiler>`: `environment.txt` and one full
  configure/build/test log per preset (debug, release, asan-ubsan, tsan).
- `tsan-repeat/`: the TSan unit-test binary run repeatedly, to give the stress tests more
  interleavings (see the Phase 2 report §15).
- `benchmarks/<compiler>/`: `scripts/run-benchmarks.sh <compiler>`:
  - `environment.json`: date, CPU, memory, cgroup limits, kernel, compiler, flags, load average.
  - `ingest.json`: Google Benchmark JSON for the baseline, the pipeline grid, the batch ablation
    and the queue micro-benchmarks (one process). `ingest.console.txt`: the same run's console.
  - `overload-*.json`: Experiment 2 (reduced), one process per queue design so peak RSS is
    attributable.
  - `runs.csv` (every repetition), `summary.csv` and `summary.md` (median, mean, stddev, 95%
    bootstrap CI), generated by `scripts/summarize-benchmarks.py` from the JSON.

Correction made by hand after the runs: `run-benchmarks.sh` wrote an invalid
`"git_uncommitted_files"` value (a two-line string, because a pipeline's fallback ran in a
non-git directory) into both `benchmarks/*/environment.json` files. The value was replaced with
`"unknown"` and an explanation, so the files are valid JSON; nothing else was edited. The script
is fixed. Load average before the runs was 3.2 (GCC) and 2.7 (Clang) because the preceding
TSan repeat run had just finished.
